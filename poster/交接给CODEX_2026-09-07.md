## 三、第 1 项：器型合并 —— 我做完的和没做的

### 已完成并上线（commit `ef222d4`）

用户的判断是对的：`k=6..11` 的光滑剪影和旋成体出的多边形**是同一个东西的两份实现**。
但直接合并会掉质量，所以我先把质量补齐了：

- `vesselPts` 从「按名字查 PROF」拆成通用的 `profPts(prof, asp, r)` / `profInto(...)`
- 新增 **`lerpProf(A,B,m)`**：两条剖面在 **t 的并集**上插值，不是重采样。
  ⚠️ 这条很重要：剖面节点上的标记（`1` = 曲率极值，切线锁竖直；`2` = 角点，不平滑）
  是绑在节点上的，**重采样会把它们全丢掉**，插出来的器物就没有肩、没有口沿。
- `latheToShape()` 正侧视时把**剖面本身**带出来（`cu.prof`），`customInto` 直接画光滑曲线，
  完全不经过多边形。`loops` 仍然带着，给量面积 / 画图标 / 俯仰那条路用。
- 俯仰那条路的 RDP 点数预算 **26 → 56**（实测 56 是拐点，再多不改善）
- `toneBuffer`（三维明暗）：带剖面的自定义形要走**旋成体那一支的真圆柱面明暗**，
  不能掉到最后那个柱面近似里 —— 否则器物一变成旋成体元素，立体就退化了
- 明暗缓存的 key 认剖面，否则不同器物共用同一张明暗图

**实测**（正侧视逐像素对照光滑剪影）：

| 器物 | 改前 | 改后 |
|---|---|---|
| 葫芦瓶 / 觚 / 碗 | 0.47% / 0.30% / 0.02% | **0%（完全一致）** |
| 梅瓶 | 0.296% | 0.107% |
| 玉壶春瓶 | 0.363% | 0.091% |
| 蒜头瓶 | 0.427% | 0.093% |

### 还没做的（合并本身）

现在 `k=6..11` 和旋成体**并存**。要真正合并，剩下这几步：

1. **每个元素带自己的 `e.lat = {a,b,m,t}`**。
   现在 `S.lat` 是**全局单例**，两个器物没法各转各的 —— 这正是「个性化拉满」的实处。
   `latheToShape()` 现在还是读 `S.lat`，要改成收显式参数 `latheToShape(lat)`。
2. **形状架上那 6 个器物按钮改成建旋成体元素**：
   `addEl(12, {cu: latheToShape({a:i-6,b:i-6,m:0,t:0}), lat:{...}})`
3. **旋成体面板改成编辑「当前选中元素」的 `lat`**（现在编辑的是 `S.lat`）。
   相关函数：`syncLathe()` / `applyLathe()` / `drawLathe()` / `curLathe()` /
   `vAEl`/`vBEl` 的 onchange / `latheEl` 的 pointer 事件 / dblclick 归零。
4. ⚠️ **`feat()` 必须加 `lat` 的维度**（a / b / m / t），否则所有器物在尺子上
   会塌成同一个点（`e.k` 全是 12），候选多样性会死。
   建议权重：`(lat.a/5)*0.50, (lat.b/5)*0.30, lat.m*0.40, lat.t*0.90`。
   **加完必须重新标定 `VARY_BAND`** —— 方法写在 `VARY_BAND` 上面那段注释里，别跳过。
5. `shuffleState()` 生成器物时给随机的 `a/b/m/t` —— 生成的海报里会出现俯仰的器物，
   这本身就是审美升级。
6. 收尾：`SHAPES` 里 6..11 的条目、`vesselInto`、`elInto` 里 `k>=6` 那一支就都成了死代码，
   可以删。但**别删 `PROF` / `profAt` / `profSegs` / `ASPECT`**，旋成体全靠它们。

**别踩的**：
- `fillRatio(12, cu)` 量的是 `cu.loops` 的多边形面积 —— 所以 `loops` 必须一直带着
- 自检「器物不被画布切掉」筛的是 `(e.k>=6 || e.k===12)`
- `elSize` / `aspOf` / `aspOfE` 对 `k=12` 读 `cu.asp`
- `custSVG()`（形状架上的图标）画的是 `C.loops`

调研 `motion.jsonl` 里要的东西：具体的 cubic-bezier / spring 参数、时长分级表、
「印出来」的逐帧编排、微交互清单（含**哪些不该加动效**）、
Canvas 2D 里怎么做高质量动画、`prefers-reduced-motion` 怎么处理。

### 第 2 项：生成器审美

`shuffleState()` 现在是一堆手写 `pick()`。约束只有：ΔL*≥30、覆盖率落在可印区间、
切线角度 0/90/±7~12°、位置 28–36%、器物不出边距、光学重量按墨面积。

调研 `generator.jsonl` 要的：构图的可计算判据、计算美学里**哪些结论可复现哪些是过度声称**、

**上一轮已经拿到但没落地的**（在 `16_落位与灵感/partial/text_placement.jsonl`）：

### 第 4 项：照片进海报

现在只有：Otsu 阈值 → 形态学 → 连通域 → marching squares → RDP，只能出**纯剪影**，

- **抠图三条路**：算法自动（GrabCut/saliency）、模型自动

## 六、这个项目里反复踩到的坑（三次了，请务必读）

### 1. 交互必须用**真实事件**测，不能调函数

- 上一次：键盘事件派发到 `window`，被 `e.target!==document.body` 挡掉，得出一堆假 bug
- 这一次：给 `showTray` 加了参数 `reuse`，但绑定还是 `onclick = showTray` ——
  **点击事件对象被当成候选列表传了进去**，用户一点「六个方向」就崩。
  所有程序化用例调的都是 `showTray()`，永远不带参数，所以测不出来。

现在自检里有一条「顶部按钮点下去真的出六个候选」，用 `dispatchEvent` 派发真实点击
并挂 `window.onerror`。**新加任何交互，都照这个写用例。**

### 2. 自检用例自己会污染自己

渲染类用例开头**必须**自己铺干净状态：`elA=1`（前一个用例的落下动画会把元素画成
`globalAlpha=0`）、纸色墨色（前一个用例可能留下「覆盖率 0」，那时墨色等于纸色，
形本身就是隐形的）、`S.dot`。四次自检失败里三次是测试自己的问题。

### 3. 断言写错比代码写错更常见

- 「台阶必须集中在切线附近」——错，版偏移本来就作用在整块版上
- 量台阶用了绝对值 —— 被器物自身的收腰抵消，读数 3→1 看着像在变小
- 量网屏相位时采样区被形的边界切到 —— 量的是形不是网屏

**写渲染类用例前先问一句：我量的这个数，真的只受我要测的那件事影响吗？**

### 4. 环境

- 仓库文件是 **CRLF**，字符串替换补丁必须先归一化成 LF 再改回去
- Bash heredoc 里放正则会被 shell 吃掉转义 —— 大补丁写成 `.mjs` 文件用 node 跑
- CDP/eval body 里**不要用中文键名**
- Python 在 `C:\Users\shune\AppData\Local\Programs\Python\Python312\python.exe`，
  不在 PATH 里（见根目录 `CLAUDE.md`）
